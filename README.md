# PiyuX Cloud

PiyuX Cloud is a self-hosted web drive that uses Telegram for file storage and provides a browser-based interface for file management, previews, streaming, share links, multi-user access, branding, and a REST API.

The application source is in the `Drive/` directory.

## Deploy on Render

This repository includes a `render.yaml` Blueprint for deployment.

1. Open [Render](https://render.com/) and create a new **Blueprint**.
2. Connect the `Piyu242005/PiyuX` repository and select the `main` branch.
3. Review the service settings and create the service.
4. When prompted, set `PUBLIC_URL` to the exact public Render URL, without a trailing slash (for example, `https://your-service.onrender.com`).
5. Keep `SECRET` generated by Render. Do not commit it or share it publicly.
6. Once deployment completes, open the service URL. Create the administrator account, then connect Telegram using your Telegram API ID and API hash from [my.telegram.org](https://my.telegram.org).

### Render configuration

The Blueprint sets:

- **Root directory:** `Drive`
- **Build command:** `npm ci`
- **Start command:** `npm start`
- **Health check:** `/api/health`
- **Persistent disk:** mounted at `/opt/render/project/src/Drive/data`
- **Runtime:** Node.js (Node 20 or later)

The persistent disk stores the SQLite database, generated backups, Telegram session data held in SQLite, uploaded branding files, and temporary application data. Keep a persistent disk attached to preserve this state across restarts and deployments. Disk availability and pricing depend on the Render plan.

## Important deployment notes

- Set `PUBLIC_URL` to the deployed HTTPS origin so public share links use the correct hostname.
- `SECRET` must remain stable across restarts; changing it can invalidate existing signed cookies or tokens.
- Do not put Telegram API credentials, passwords, session strings, or `.env` values in source control. Use Render environment variables.
- Telegram-backed storage is subject to Telegram's file-size, API, account, and rate limits; it should not be described as guaranteed unlimited storage.
- This application uses SQLite and a single persistent disk. Run a single service instance unless you migrate the stateful database and session architecture to a shared database.
- Large uploads/downloads may be subject to platform, client, proxy, or request time limits. Validate large-file behavior on the selected Render plan before relying on it.
- The `/api/health` route checks that the web process responds; it does not verify Telegram connectivity.

## Local development

Requirements: Node.js 20 or later.

```bash
cd Drive
npm ci
cp .env.example .env
# Set SECRET to a random string of at least 32 characters.
npm start
```

Open http://127.0.0.1:3001.

## Project layout

- `Drive/src/server.js` — Express server and static frontend
- `Drive/src/routes/` — API routes
- `Drive/src/tg/` — Telegram client and file operations
- `Drive/src/db.js` — SQLite schema, migrations, and backups
- `Drive/public/` — web interface
- `render.yaml` — Render Blueprint
